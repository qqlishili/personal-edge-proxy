# 自建个人 VPN / 代理：VPS 怎么选

这篇解决的是部署之前最容易被低估的问题：**机器怎么买。**

本项目的经验是：CPU、内存和宣传带宽通常不是最难选的；真正决定日常体验的，往往是**线路、丢包、晚高峰、UDP 可用性、服务商政策、最终出口和故障恢复能力**。

> 本文面向个人远程访问、网络工程学习和开发测试。购买和使用云服务器前，请确认所在地区法律法规、云服务商 AUP / ToS 以及目标服务条款。

---

## 0. 先记住一个“不可能三角”：价格 × 配置 × 线路

这是我自己选 VPS 时很喜欢用的一个判断框架。它不是数学定律，而是一条很实用的采购经验：

```text
                    线路 / 速度
             延迟 · 丢包 · 晚高峰
                UDP · 稳定吞吐
                       ▲
                      / \
                     /   \
                    /     \
                   /       \
                  /         \
           配置 ◀────────────▶ 价格
      CPU / RAM / SSD       实际长期成本
      流量 / 端口带宽       折扣 / 续费价
```

通常很难在同一个低价套餐里同时拿到：

```text
很便宜
+
配置特别高
+
中国方向线路也特别好
```

更常见的情况是：

| 组合 | 常见代价 |
|---|---|
| 便宜 + 配置高 | 线路普通、共享带宽、晚高峰不确定，或者流量 / 网络资源更紧 |
| 便宜 + 线路好 | CPU、RAM、磁盘、流量或端口带宽通常比较克制 |
| 配置高 + 线路好 | 月付价格通常明显上升 |

所以这个“不可能三角”的目的不是让你放弃某一角，而是：

> **根据自己的用途先给三角形三个角分配权重，再在预算内找到整体最平衡的那台机器。**

### 三个角具体看什么

#### 价格

不要只看商品页最大的那个促销数字。真正应该算的是**有效长期月成本**：

```text
套餐价格
+ IPv4 费用
+ 机房 / 地区附加费
+ 税费 / 服务费
+ 必要附加项
--------------------------------
          实际购买周期
```

还要确认：

- 优惠是首月、首年，还是循环续费；
- 续费价是否和首购价相同；
- 月付、季付、年付分别多少钱；
- 是否有 setup fee；
- 流量超额后是停机、限速还是额外计费；
- IPv4、备份、快照、换 IP 是否另外收费。

**折扣是很值得利用的变量。** 黑五、周年活动、季节促销、优惠码等，经常可以把价格这一角往下压，而不必主动牺牲配置或线路。

但第一次接触某个厂商时，我仍然更愿意：

```text
先月付验证
    ↓
线路和实例都通过
    ↓
再考虑长期优惠 / 年付
```

不要为了一个漂亮的年付折扣，把自己锁在一条还没有实测过的线路上。

#### 配置

这里主要看：

```text
CPU
RAM
SSD / NVMe
月流量
端口带宽
公网 IPv4
虚拟化类型
```

个人 HY2 / Xray 中转通常并不吃 CPU 和内存。对只跑代理核心和少量辅助服务的机器来说，`1 vCPU + 1 GB RAM` 往往已经跨过“够用线”。

一旦跨过够用线，继续从 `1C1G` 堆到 `4C8G`，对代理体验的提升通常远小于把预算换成更好的线路和更稳定的晚高峰。

如果 VPS 还要承担数据库、网站、编译、容器或其他长期服务，那配置权重当然要重新提高。

#### 线路 / 速度

这里的“速度”绝对不只是商品页上的 `1 Gbps`。

我更在意：

```text
RTT 延迟
P95 / 最大延迟
丢包
抖动
晚高峰变化
持续吞吐
UDP 可达性
路由稳定性
```

所以：

```text
1 Gbps 共享端口 + 晚高峰严重丢包
```

完全可能不如：

```text
200 Mbps + 低抖动 + 0% 终点丢包 + 稳定 UDP
```

对个人代理来说，后者往往更好用。

### 不同用途，三角形权重应该不同

可以粗略理解成：

| 用途 | 第一优先 | 第二优先 | 第三优先 |
|---|---|---|---|
| 日常 HY2 / VPN 中转 | 线路 | 价格 | 配置跨过够用线即可 |
| AI / SaaS 入口机 | 线路 / UDP | 价格 | 配置 |
| 网站 + 数据库 + 代理一体机 | 线路 ≈ 配置 | 价格 | — |
| 备用节点 / 灾备节点 | 价格 | 线路够稳定 | 配置 |
| 编译 / 容器 / 计算节点 | 配置 | 价格 | 线路按业务需要 |

这也是为什么两台同样 `$10/月` 的机器：

```text
A：4C / 8G / 1Gbps，普通国际线路
B：1C / 1G / 200Mbps，但你到它的晚高峰线路更稳
```

如果目标只是做个人中转，B 完全可能是更优解。

**最优 VPS 不是参数最大的那台，而是最符合你自己的三角权重、且实际测出来最稳定的那台。**

## 1. 先明确：你到底在选哪一段网络

最简单的结构是：

```text
Client
  ↓
VPS
  ↓
Internet
```

这其实包含两段完全不同的问题：

```text
入口：你的网络 -> VPS
出口：VPS -> 目标网站 / 服务
```

如果再加入 WARP 或固定上游：

```text
Client
  ↓
VPS
  ├─ ordinary traffic -> VPS Direct
  ├─ selected traffic -> WARP
  └─ selected traffic -> Fixed SOCKS5
```

那么 VPS 自己的任务更偏向：

- 让你稳定地连进去；
- 承载协议和 routing；
- 稳定地连接 WARP / 上游；
- 在故障时容易排查和恢复。

所以不要把“VPS 原生 IP 看起来怎么样”当成唯一选机标准，也不要只看宣传页上的 CPU 和 `1 Gbps`。

## 2. 第一轮：先用硬条件把不合适的厂商删掉

个人 HY2 / Xray 节点并不吃配置。基础目标通常是：

```text
1 vCPU
1 GB RAM
20~50 GB disk
Ubuntu 24.04 LTS / Debian 12+
公网 IPv4
TCP + UDP
100~200 Mbps 或更高稳定带宽
```

如果还要跑 WARP、日志、监控或其他小服务，`2 GB RAM` 会更从容，但并不是必须。

真正应该先问的是：

| 项目 | 为什么重要 |
|---|---|
| 公网 IPv4 | 避免 NAT VPS 带来的端口和入站限制 |
| UDP 可用 | HY2 / QUIC 依赖 UDP |
| Root / sudo | 需要自己管理服务、systemd、防火墙等 |
| AUP 允许目标用途 | 有的厂商明确限制 VPN、Proxy、Tunnel 或高 UDP 流量 |
| 月付 | 第一次买某家时降低线路踩坑成本 |
| Test IP / Looking Glass | 不买机器就能先测入口线路 |
| 重装系统 / Web Console | SSH 配坏、防火墙配错时能自救 |
| 明确流量额度 | 防止“带宽很高但月流量很小” |
| 续费价格明确 | 不要只看首月促销价 |
| IP 更换规则 | 新 IP 异常、地理定位错误时方便处理 |

如果连 AUP、UDP、测试 IP、续费价格都说不清，我通常不会直接年付。

## 3. 地区怎么选：物理距离只是第一层

“离我最近”通常是一个不错的起点，但**不是结论**。

同样是东京机房，不同 ASN、不同上游、不同回程线路，在同一个本地运营商上可能完全不是一个体验。

更实际的思路：

```text
你的网络
  ↓
候选地区 A / B / C
  ↓
候选厂商不同线路
  ↓
实测后再选
```

如果你的主要使用地在中国大陆，常见候选会包括：

- 日本东京 / 大阪；
- 韩国首尔；
- 中国香港；
- 新加坡；
- 美国西海岸。

但不要把这张表理解为固定排名。中国电信、联通、移动，甚至同一省不同宽带之间，结果都可能不同。

**“优化线路”“精品网”“国际精品”只能当候选标签，不能替代实测。**

### 3.1 国内三大运营商：更值得关注的线路参考

下面这张表只用来帮助你看懂 VPS 商品页和 traceroute。它是**候选过滤器，不是购买答案**。

| 本地运营商 | 普通常见网络 | 更值得关注的优化 / 精品方向 | 常见 ASN / 识别线索 | 需要注意 |
|---|---|---|---|---|
| 中国电信 | ChinaNet / 163，常见 `AS4134` | **CN2**，市场上尤其常见 `CN2 GIA` 作为高质量标签 | `AS4809`；路由里经常能看到 `59.43.*.*` 段 | 看到 AS4809 不等于自动证明“全程 GIA”；GT / GIA、去程 / 回程、接入城市都要继续核对 |
| 中国联通 | 169 网，常见 `AS4837` | **AS9929 + AS10099**，市场常称 CUP / China Unicom Premium / 联通精品 | 国内精品骨干 `AS9929` + 联通国际 `AS10099` | 只有 AS10099、只有一侧出现 AS9929，和双向完整精品路径不是一回事 |
| 中国移动 | CMNET / 普通国际 CMI | **CMIN2** | 普通 CMI 常见 `AS58453`；CMIN2 为 `AS58807` | `CMI` 和 `CMIN2` 不要混为一谈；仍要看本地省份和双向实测 |

这里最容易犯的错是：

> **看到一个漂亮的线路名，就把它当成性能保证。**

实际上还要继续问：

```text
谁的线路？
电信 / 联通 / 移动哪一家优化？
去程优化还是回程优化？
两边是否对称？
从哪个城市出境 / 入境？
晚高峰还是不是同一条路？
我的省份是否真的走到这条线路？
```

例如电信商品页写 `CN2`，并不能只凭四个字判断它在你这里一定比另一台普通 Transit 更快。

#### 电信：CN2 / AS4809

`AS4809` 对应 China Telecom / CN2。

市场里常见：

```text
163 / ChinaNet
CN2
CN2 GT
CN2 GIA
```

其中 `CN2 GIA` 常被用于强调更高质量的 CN2 接入，但**商品标签本身不能代替路由证据**。

实际验收时更应该看：

- traceroute / MTR 是否实际进入 AS4809；
- 是否只是某一小段借道；
- 去程、回程是否一致；
- 晚高峰是否仍然稳定；
- 最终端到端丢包和抖动怎么样。

路由里看到 `59.43.*.*` 经常与 CN2 段有关，但也不要只凭 IP 前缀下结论，最好同时核对 ASN。

参考：<https://www.peeringdb.com/asn/4809>

#### 联通：AS9929 + AS10099

联通常见几个名字：

```text
AS4837   -> 联通普通 169 骨干
AS9929   -> 联通精品 / A 网方向
AS10099  -> China Unicom Global 国际网络
```

对海外 VPS 来说，更值得关注的一种结构通常类似：

```text
联通家宽 / AS4837
        ↓
AS9929
        ↓
AS10099
        ↓
海外 VPS / 上游
```

这类组合在 VPS 市场经常被叫：

```text
CUP
China Unicom Premium
联通精品
9929
```

但如果商品页只写 `9929`，仍然应该看实际路由，确认是不是你所在地区、你使用的方向真的进入 AS9929 / AS10099。

参考：

- <https://www.peeringdb.com/net/19957>
- <https://www.peeringdb.com/asn/10099>

#### 移动：CMI 与 CMIN2

这个非常容易看错：

```text
CMI    -> 中国移动国际常规网络，常见 AS58453
CMIN2  -> China Mobile International NII，AS58807
```

如果商家写“移动精品”“CMIN2”，可以把 `AS58807` 当成一个重要核对点。

但同样不要把 ASN 本身当性能保证：

- 本地省份接入不同；
- 去回程可能不对称；
- 不同时段可能调路由；
- 海外最后一段的 Transit 也会影响体验。

参考：

- 普通 CMI：<https://www.peeringdb.com/asn/58453>
- CMIN2：<https://www.peeringdb.com/asn/58807>

### 3.2 日本 VPS 常见的 SoftBank / IIJ / NTT 又是什么？

这些名字和 `CN2 / 9929 / CMIN2` 不是同一个层级的概念。

常见日本 / 国际上游包括：

| 名称 | 常见 ASN | 怎么理解 |
|---|---:|---|
| SoftBank / 软银 | `AS17676` | 日本大型骨干 / Transit，上游本身并不等于“三网精品” |
| IIJ | `AS2497` | 日本大型独立 ISP / 骨干网络 |
| NTT Global IP Network | `AS2914` | 全球 Tier-1 IP Backbone |

一条完整路径完全可能同时出现：

```text
中国电信
  ↓
CN2 / AS4809
  ↓
日本交接
  ↓
NTT / IIJ / SoftBank
  ↓
Tokyo VPS
```

或者：

```text
中国联通
  ↓
AS9929 / AS10099
  ↓
SoftBank
  ↓
Tokyo VPS
```

所以：

> **SoftBank / IIJ / NTT 更像是在回答“海外这一段由谁承载”；CN2 / 9929 / CMIN2 更像是在回答“中国三大运营商这一段用了什么网络等级”。**

不能简单问“软银和 CN2 哪个更好”，因为它们可能本来就在同一条端到端路径的不同位置。

参考：

- SoftBank AS17676：<https://www.softbank.jp/business/service/network/smart-internet/lineup/dc-connect-s>
- IIJ AS2497：<https://www-w.iw.iij.ad.jp/en/svcsol/service-providers/>
- NTT AS2914：<https://www.gin.ntt.net/>

### 3.3 “三网优化”不是一个固定线路名

`三网优化` 往往是商家的路由策略描述，不对应唯一 ASN。

理想化情况下可能是：

```text
电信 -> CN2
联通 -> AS9929 / AS10099
移动 -> CMIN2
```

但也可能只是：

```text
电信 -> 精品
联通 -> 普通但调过入口
移动 -> 普通 CMI
```

仍然被商品页写成“三网优化”。

所以对“三网优化”最正确的使用方式是：

```text
看到标签
  ↓
加入候选
  ↓
分别找电信 / 联通 / 移动测试结果
  ↓
从自己的网络实测
```

**线路名是筛选线索，不是最终证据。**

## 4. 买之前：至少拿 Test IP 做这三件事

### Windows

```powershell
ping TEST_IP -n 50
tracert -d TEST_IP
pathping TEST_IP
```

### Linux / macOS

```bash
ping -c 50 TEST_IP
mtr -rwzbc 50 TEST_IP
```

重点不要只看“平均延迟”。

更应该看：

1. **丢包**：终点最好接近 `0%`；
2. **抖动**：min / avg / max 不要差得离谱；
3. **路径稳定性**：不同时间 traceroute 是否经常大幅变化；
4. **晚高峰**：白天好看、晚上炸掉的线路没有意义；
5. **运营商差异**：如果你手机和宽带不是同一家运营商，最好都测。

推荐至少测两个时间段：

```text
白天
20:00 ~ 23:00 晚高峰
```

注意：中间某一跳 `*` 或 ICMP 丢包，不一定代表真实业务流量也丢。最终目标的端到端表现更重要。

### 去程和回程最好分开看

互联网路由经常是不对称的：

```text
你 -> VPS
```

和：

```text
VPS -> 你
```

可能根本不是同一条路径。

所以商家说“回程 CN2”“三网回程优化”时，不要自动理解成双向都一样。

本地 `traceroute / tracert` 主要帮助你看本地到 VPS 的方向；如果需要认真判断反向路径，可以结合：

- VPS 侧 traceroute / mtr；
- 厂商 Looking Glass；
- 支持反向测试的第三方探针；
- 多运营商 Looking Glass。

## 5. Ping 低不等于节点好

一个常见误区：

```text
机器 A：45 ms，但晚高峰 5% 丢包
机器 B：65 ms，但长期 0% 丢包
```

个人代理 / VPN 场景里，我通常更愿意选 B。

因为实际体验更怕：

- 随机超时；
- QUIC 重传；
- 长连接断裂；
- 晚高峰抖动；
- 上传突然掉速。

而不是怕多二三十毫秒 RTT。

同理：

> **稳定的 200 Mbps，通常比严重超售的“共享 1 Gbps”更有价值。**

## 6. 买到机器后：不要立刻宣布“这家真香”

第一次只买一个月，然后做验收。

### 基础检查

```bash
curl -4 https://api.ipify.org
ip route
free -h
df -h
```

确认：

- 公网地址与你购买的资源一致；
- 默认路由正常；
- CPU / RAM / Disk 没有明显缩水；
- DNS、IPv4 出站正常。

### 再从本地重测

```powershell
ping YOUR_SERVER_IP -n 50
tracert -d YOUR_SERVER_IP
```

这次测的是真实实例，不是厂商共享 Test IP。

如果有另一台你控制的服务器，可以再使用 `iperf3` 验证持续 TCP / UDP 吞吐，而不是只跑一次网页测速。

## 7. HY2 用户必须单独测试 UDP

这是我们自己选机时踩过、也最值得写进教程的一点。

**TCP 正常，不代表 UDP 正常；UDP 正常，也不代表所有 UDP 端口都一样。**

例如可以在服务端抓包：

```bash
sudo tcpdump -ni any 'udp port 443 or udp port 24443'
```

然后从客户端分别尝试 UDP `443` 和 `24443`。

如果出现：

```text
UDP 24443 -> 包正常到达 VPS
UDP   443 -> VPS 完全看不到包
```

更像是中间链路对 `UDP/443` 做了特殊处理，而不是“UDP 整体不可用”。

这时不要只盯着协议配置改半天。

### HY2 一定要 UDP 443 吗？

不需要。

QUIC / HY2 可以跑在其他 UDP 端口。`443` 很常见，也更接近普通 HTTP/3 的端口习惯，但**端口选择最终仍应服从实际可达性和稳定性**。

推荐思路：

```text
先试 UDP 443
    ↓
稳定 -> 可以用
    ↓
异常 -> 对照测试 UDP 24443 / 其他高位端口
    ↓
以实测结果为准
```

而且 `TCP 443` 与 `UDP 443` 属于不同传输层端口空间，所以理论上可以同时运行：

```text
TCP 443 -> REALITY
UDP 443 -> HY2
```

是否采用，仍然取决于你的真实网络路径。

## 8. 带宽和月流量怎么看

先分清两个概念：

```text
带宽：某一时刻能跑多快
流量：一个月累计能传多少
```

例如：

```text
200 Mbps
800 GB / month
```

对于个人使用通常已经很充裕。

不要因为看到：

```text
1 Gbps
```

就自动认为更好。还要问：

- 是独享还是共享？
- 晚高峰能跑多少？
- 国际方向是否限速？
- 流量双向计费还是单向？
- 超流量后停机、限速还是按量收费？

如果是第一次接触的小厂，我更看重**稳定和规则透明**，而不是峰值数字。

## 9. 如果主要拿来用 AI，选 VPS 时多看一层“出口”

如果架构是：

```text
AI traffic -> VPS Direct
```

那么 VPS 原生公网 IP 的地区、ASN、数据中心属性和历史信誉都会直接暴露给目标服务。

如果架构是本项目推荐的：

```text
ordinary traffic          -> VPS Direct
selected AI traffic       -> WARP
selected fixed-egress app -> Fixed SOCKS5
```

那么选 VPS 时，可以把更多权重放在：

- 你到 VPS 的线路；
- VPS 的 UDP 稳定性；
- VPS 到 WARP / 上游的连接质量；
- 服务商可靠性；
- 运维和恢复能力。

而不是把所有希望都压在 VPS 原生 IP 上。

但仍要注意：

- WARP 不是住宅 IP；
- 数据中心 / WARP / 固定出口都不能保证某个服务一定接受；
- 目标服务的支持地区和风控策略会变化；
- 不要把“降低依赖”写成“保证不封号”。

## 10. 中国内地云服务器能不能做 VPN？

**从技术上说，当然存在合法的 VPN / 加密隧道使用场景。**

国内大型云平台本身就提供 VPN Gateway，用于 VPC 与本地 IDC、不同网络环境之间建立加密连接。例如腾讯云官方文档明确描述了通过公网加密通道连接 VPC 与本地数据中心的 VPN 方案。

但是，需要把几个问题分开：

### 场景 A：自己的设备 / IDC / VPC 做私网互联

这是标准的企业网络和云网络场景，可以使用云厂商提供的 VPN Gateway、专线、云联网等合规产品。

### 场景 B：把中国内地 VPS 当成普通云主机跑一个私有加密隧道

技术上能否跑，与安全组、系统权限和厂商 AUP 有关；具体用途还需要符合当地法规和服务商条款。

### 场景 C：把中国内地 VPS 当作跨境代理出口或对外经营 VPN / 代理服务

不要把它简单等同于“买一台海外 VPS 自建节点”。

中国内地的跨境通信、电信业务经营、国际专线等存在专门监管要求。工信部对相关政策的公开答复曾明确区分：监管重点包括未经许可开展跨境电信业务经营；企业因办公自用需要跨境联网时，应通过依法设置国际通信出入口的电信业务经营者获得相应服务。

所以本项目不会给出“买一台中国内地云服务器，然后把它当通用跨境出口”的部署建议。

更实用的判断是：

```text
境内私网互联 / 办公网 -> 可以认真考虑国内云 VPN 产品
海外最终出口需求      -> 通常直接评估海外节点更清晰
跨境企业专网           -> 走运营商 / 云厂商合规方案
对外经营代理/VPN       -> 先处理资质与合规问题
```

另外，**中国香港节点不能简单当成“中国内地节点”来讨论**。网络路径、云产品规则和适用环境都可能不同，选型时应单独测试和核对。

这部分不是法律意见；法规、云平台政策和产品能力都可能变化，实际使用前请查当前官方说明。

官方参考：

- 工信部关于清理规范互联网网络接入服务市场的政策答记者问：<https://www.cac.gov.cn/2017-01/26/c_1120381529.htm>
- 工信部关于 VPN / 跨境办公联网的公开答复：<https://bzxx.miit.gov.cn/bzxx/reply/detail?appellateId=8a8283846da73d1f016da9b7af1e00a2&id=8a8283846da73d1f016da9b7af1e00a2>
- 《国际通信出入口局管理办法》：<https://www.miit.gov.cn/zcfg/xxtxl/art/2009/art_743e180625b541b0800931226bbad38a.html>
- 腾讯云 VPC 连接方案概述：<https://cloud.tencent.com/document/product/215/37053>

## 11. 一套实际可执行的筛选流程

我更推荐下面这种顺序：

```text
1. 明确用途，并给“价格 / 配置 / 线路”分配优先级
2. 给三个角分别设最低线和预算上限
3. 根据自己的本地运营商确定值得优先看的线路标签
4. 列出 5~10 家候选
5. 先查 AUP / UDP / 月付 / 流量 / 公网 IP
6. 核对首购价、续费价、IPv4 / 机房附加费和可用优惠
7. 删除硬条件不满足的
8. 找 Test IP / Looking Glass
9. 白天 ping + traceroute
10. 晚高峰再测一次
11. 只剩 2~3 家后，先月付一台
12. 实例到手重新测线路
13. 单独测试 UDP 443 / 高位 UDP
14. 部署最小 HY2，真实使用几天
15. 通过后再考虑长期折扣、年付、WARP 或备用入口
```

关键原则：

> **一次只验证一层，不要先买一年，也不要先装全家桶。**

折扣最好放在“候选已经合格”以后比较，而不是反过来因为便宜先买一台再祈祷线路好。

## 12. 用“不可能三角”给候选 VPS 打分

硬条件不满足的直接淘汰；剩下的再评分。

最简单的办法是把候选拆成四项：

```text
线路分
配置分
价格分
运维 / AUP 分
```

然后根据自己的用途分配权重。

### 例 1：日常 HY2 / AI 中转

```text
线路        50%
价格        25%
配置        15%
运维 / AUP  10%
```

这里线路分里再看：

- 本地到 VPS 稳定性；
- 晚高峰丢包 / 抖动；
- UDP；
- 持续吞吐；
- 到 WARP / 固定上游的质量。

### 例 2：网站 / 数据库 / 代理一体机

```text
线路        35%
配置        35%
价格        20%
运维 / AUP  10%
```

### 例 3：备用节点

```text
价格        40%
线路        30%
配置        15%
运维 / AUP  15%
```

这里没有标准答案。

真正的思路是：

```text
先设最低线
   ↓
超过最低线以后，不再盲目堆某一个角
   ↓
把预算放到自己真正敏感的另外两角
   ↓
利用折扣继续压低有效成本
```

比如个人代理已经有 `1C1G`，继续花钱买 `8G RAM` 可能没有意义；如果晚高峰线路差，把同样的钱换到更好的 Transit / 精品回程上，收益通常更明显。

如果最终所有流量都用 VPS Direct，可以提高“原生 IP / 出口质量”的权重。

如果主要是 `HY2 -> VPS -> WARP / Fixed SOCKS5`，则应该提高“入口线路和 UDP”的权重。

## 14. 最后一个经验：不要迷信厂商，也不要迷信线路名

今天很好的线路，几个月后可能换上游；某个地区别人很好用，在你的运营商上也可能完全不同。

商品页里的这些词：

```text
CN2
CN2 GIA
9929
CUP
CMI
CMIN2
SoftBank
IIJ
NTT
三网优化
精品网
原生 IP
双 ISP
```

都只能帮助你**形成候选**。

它们不能代替：

```text
看规则
  ↓
查实际价格 / 折扣 / 续费
  ↓
测线路
  ↓
月付试机
  ↓
测 UDP
  ↓
真实部署
  ↓
晚高峰持续观察
```

所以这篇教程最后的结论不是“哪一家 VPS 最好”，也不是“哪一种线路天下第一”。

真正目标是：

> **用价格、配置、线路这个“不可能三角”建立自己的权重，在满足硬条件之后尽量取得平衡，找到当前最符合个人需求的最优解。**

然后永远保留最后一条原则：

**实测比宣传更重要。**
