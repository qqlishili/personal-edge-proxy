# 自建个人 VPN / 代理：VPS 怎么选

这篇解决的是部署之前最容易被低估的问题：**机器怎么买。**

本项目的经验是：CPU、内存和宣传带宽通常不是最难选的；真正决定日常体验的，往往是**线路、丢包、晚高峰、UDP 可用性、服务商政策、最终出口和故障恢复能力**。

> 本文面向个人远程访问、网络工程学习和开发测试。购买和使用云服务器前，请确认所在地区法律法规、云服务商 AUP / ToS 以及目标服务条款。

---

## 1. 先明确：你到底在选哪一段网络

最简单的结构是：

```text
Client
  ↓
VPS
  ↓
Internet
```

这其实包含两段完全不同的问题：

```text
入口：你的网络 -> VPS
出口：VPS -> 目标网站 / 服务
```

如果再加入 WARP 或固定上游：

```text
Client
  ↓
VPS
  ├─ ordinary traffic -> VPS Direct
  ├─ selected traffic -> WARP
  └─ selected traffic -> Fixed SOCKS5
```

那么 VPS 自己的任务更偏向：

- 让你稳定地连进去；
- 承载协议和 routing；
- 稳定地连接 WARP / 上游；
- 在故障时容易排查和恢复。

所以不要把“VPS 原生 IP 看起来怎么样”当成唯一选机标准，也不要只看宣传页上的 CPU 和 `1 Gbps`。

---

## 2. 第一轮：先用硬条件把不合适的厂商删掉

个人 HY2 / Xray 节点并不吃配置。基础目标通常是：

```text
1 vCPU
1 GB RAM
20~50 GB disk
Ubuntu 24.04 LTS / Debian 12+
公网 IPv4
TCP + UDP
100~200 Mbps 或更高稳定带宽
```

如果还要跑 WARP、日志、监控或其他小服务，`2 GB RAM` 会更从容，但并不是必须。

真正应该先问的是：

| 项目 | 为什么重要 |
|---|---|
| 公网 IPv4 | 避免 NAT VPS 带来的端口和入站限制 |
| UDP 可用 | HY2 / QUIC 依赖 UDP |
| Root / sudo | 需要自己管理服务、systemd、防火墙等 |
| AUP 允许目标用途 | 有的厂商明确限制 VPN、Proxy、Tunnel 或高 UDP 流量 |
| 月付 | 第一次买某家时降低线路踩坑成本 |
| Test IP / Looking Glass | 不买机器就能先测入口线路 |
| 重装系统 / Web Console | SSH 配坏、防火墙配错时能自救 |
| 明确流量额度 | 防止“带宽很高但月流量很小” |
| 续费价格明确 | 不要只看首月促销价 |
| IP 更换规则 | 新 IP 异常、地理定位错误时方便处理 |

如果连 AUP、UDP、测试 IP、续费价格都说不清，我通常不会直接年付。

## 3. 地区怎么选：物理距离只是第一层

“离我最近”通常是一个不错的起点，但**不是结论**。

同样是东京机房，不同 ASN、不同上游、不同回程线路，在同一个本地运营商上可能完全不是一个体验。

更实际的思路：

```text
你的网络
  ↓
候选地区 A / B / C
  ↓
候选厂商不同线路
  ↓
实测后再选
```

如果你的主要使用地在中国大陆，常见候选会包括：

- 日本东京 / 大阪；
- 韩国首尔；
- 中国香港；
- 新加坡；
- 美国西海岸。

但不要把这张表理解为固定排名。中国电信、联通、移动，甚至同一省不同宽带之间，结果都可能不同。

**“优化线路”“精品网”“国际精品”只能当候选标签，不能替代实测。**

---

## 4. 买之前：至少拿 Test IP 做这三件事

### Windows

```powershell
ping TEST_IP -n 50
tracert -d TEST_IP
pathping TEST_IP
```

### Linux / macOS

```bash
ping -c 50 TEST_IP
mtr -rwzbc 50 TEST_IP
```

重点不要只看“平均延迟”。

更应该看：

1. **丢包**：终点最好接近 `0%`；
2. **抖动**：min / avg / max 不要差得离谱；
3. **路径稳定性**：不同时间 traceroute 是否经常大幅变化；
4. **晚高峰**：白天好看、晚上炸掉的线路没有意义；
5. **运营商差异**：如果你手机和宽带不是同一家运营商，最好都测。

推荐至少测两个时间段：

```text
白天
20:00 ~ 23:00 晚高峰
```

注意：中间某一跳 `*` 或 ICMP 丢包，不一定代表真实业务流量也丢。最终目标的端到端表现更重要。

---

## 5. Ping 低不等于节点好

一个常见误区：

```text
机器 A：45 ms，但晚高峰 5% 丢包
机器 B：65 ms，但长期 0% 丢包
```

个人代理 / VPN 场景里，我通常更愿意选 B。

因为实际体验更怕：

- 随机超时；
- QUIC 重传；
- 长连接断裂；
- 晚高峰抖动；
- 上传突然掉速。

而不是怕多二三十毫秒 RTT。

同理：

> **稳定的 200 Mbps，通常比严重超售的“共享 1 Gbps”更有价值。**

---

## 6. 买到机器后：不要立刻宣布“这家真香”

第一次只买一个月，然后做验收。

### 基础检查

```bash
curl -4 https://api.ipify.org
ip route
free -h
df -h
```

确认：

- 公网地址与你购买的资源一致；
- 默认路由正常；
- CPU / RAM / Disk 没有明显缩水；
- DNS、IPv4 出站正常。

### 再从本地重测

```powershell
ping YOUR_SERVER_IP -n 50
tracert -d YOUR_SERVER_IP
```

这次测的是真实实例，不是厂商共享 Test IP。

如果有另一台你控制的服务器，可以再使用 `iperf3` 验证持续 TCP / UDP 吞吐，而不是只跑一次网页测速。

## 7. HY2 用户必须单独测试 UDP

这是我们自己选机时踩过、也最值得写进教程的一点。

**TCP 正常，不代表 UDP 正常；UDP 正常，也不代表所有 UDP 端口都一样。**

例如可以在服务端抓包：

```bash
sudo tcpdump -ni any 'udp port 443 or udp port 24443'
```

然后从客户端分别尝试 UDP `443` 和 `24443`。

如果出现：

```text
UDP 24443 -> 包正常到达 VPS
UDP   443 -> VPS 完全看不到包
```

更像是中间链路对 `UDP/443` 做了特殊处理，而不是“UDP 整体不可用”。

这时不要只盯着协议配置改半天。

### HY2 一定要 UDP 443 吗？

不需要。

QUIC / HY2 可以跑在其他 UDP 端口。`443` 很常见，也更接近普通 HTTP/3 的端口习惯，但**端口选择最终仍应服从实际可达性和稳定性**。

推荐思路：

```text
先试 UDP 443
    ↓
稳定 -> 可以用
    ↓
异常 -> 对照测试 UDP 24443 / 其他高位端口
    ↓
以实测结果为准
```

而且 `TCP 443` 与 `UDP 443` 属于不同传输层端口空间，所以理论上可以同时运行：

```text
TCP 443 -> REALITY
UDP 443 -> HY2
```

是否采用，仍然取决于你的真实网络路径。

## 8. 带宽和月流量怎么看

先分清两个概念：

```text
带宽：某一时刻能跑多快
流量：一个月累计能传多少
```

例如：

```text
200 Mbps
800 GB / month
```

对于个人使用通常已经很充裕。

不要因为看到：

```text
1 Gbps
```

就自动认为更好。还要问：

- 是独享还是共享？
- 晚高峰能跑多少？
- 国际方向是否限速？
- 流量双向计费还是单向？
- 超流量后停机、限速还是按量收费？

如果是第一次接触的小厂，我更看重**稳定和规则透明**，而不是峰值数字。

## 9. 如果主要拿来用 AI，选 VPS 时多看一层“出口”

如果架构是：

```text
AI traffic -> VPS Direct
```

那么 VPS 原生公网 IP 的地区、ASN、数据中心属性和历史信誉都会直接暴露给目标服务。

如果架构是本项目推荐的：

```text
ordinary traffic          -> VPS Direct
selected AI traffic       -> WARP
selected fixed-egress app -> Fixed SOCKS5
```

那么选 VPS 时，可以把更多权重放在：

- 你到 VPS 的线路；
- VPS 的 UDP 稳定性；
- VPS 到 WARP / 上游的连接质量；
- 服务商可靠性；
- 运维和恢复能力。

而不是把所有希望都压在 VPS 原生 IP 上。

但仍要注意：

- WARP 不是住宅 IP；
- 数据中心 / WARP / 固定出口都不能保证某个服务一定接受；
- 目标服务的支持地区和风控策略会变化；
- 不要把“降低依赖”写成“保证不封号”。

## 10. 中国内地云服务器能不能做 VPN？

**从技术上说，当然存在合法的 VPN / 加密隧道使用场景。**

国内大型云平台本身就提供 VPN Gateway，用于 VPC 与本地 IDC、不同网络环境之间建立加密连接。例如腾讯云官方文档明确描述了通过公网加密通道连接 VPC 与本地数据中心的 VPN 方案。

但是，需要把几个问题分开：

### 场景 A：自己的设备 / IDC / VPC 做私网互联

这是标准的企业网络和云网络场景，可以使用云厂商提供的 VPN Gateway、专线、云联网等合规产品。

### 场景 B：把中国内地 VPS 当成普通云主机跑一个私有加密隧道

技术上能否跑，与安全组、系统权限和厂商 AUP 有关；具体用途还需要符合当地法规和服务商条款。

### 场景 C：把中国内地 VPS 当作跨境代理出口或对外经营 VPN / 代理服务

不要把它简单等同于“买一台海外 VPS 自建节点”。

中国内地的跨境通信、电信业务经营、国际专线等存在专门监管要求。工信部对相关政策的公开答复曾明确区分：监管重点包括未经许可开展跨境电信业务经营；企业因办公自用需要跨境联网时，应通过依法设置国际通信出入口的电信业务经营者获得相应服务。

所以本项目不会给出“买一台中国内地云服务器，然后把它当通用跨境出口”的部署建议。

更实用的判断是：

```text
境内私网互联 / 办公网 -> 可以认真考虑国内云 VPN 产品
海外最终出口需求      -> 通常直接评估海外节点更清晰
跨境企业专网           -> 走运营商 / 云厂商合规方案
对外经营代理/VPN       -> 先处理资质与合规问题
```

另外，**中国香港节点不能简单当成“中国内地节点”来讨论**。网络路径、云产品规则和适用环境都可能不同，选型时应单独测试和核对。

这部分不是法律意见；法规、云平台政策和产品能力都可能变化，实际使用前请查当前官方说明。

官方参考：

- 工信部关于清理规范互联网网络接入服务市场的政策答记者问：<https://www.cac.gov.cn/2017-01/26/c_1120381529.htm>
- 工信部关于 VPN / 跨境办公联网的公开答复：<https://bzxx.miit.gov.cn/bzxx/reply/detail?appellateId=8a8283846da73d1f016da9b7af1e00a2&id=8a8283846da73d1f016da9b7af1e00a2>
- 《国际通信出入口局管理办法》：<https://www.miit.gov.cn/zcfg/xxtxl/art/2009/art_743e180625b541b0800931226bbad38a.html>
- 腾讯云 VPC 连接方案概述：<https://cloud.tencent.com/document/product/215/37053>

## 11. 一套实际可执行的筛选流程

我更推荐下面这种顺序：

```text
1. 明确用途和预算
2. 列出 5~10 家候选
3. 先查 AUP / UDP / 月付 / 流量 / 公网 IP
4. 删除硬条件不满足的
5. 找 Test IP / Looking Glass
6. 白天 ping + traceroute
7. 晚高峰再测一次
8. 只剩 2~3 家后，先月付一台
9. 实例到手重新测线路
10. 单独测试 UDP 443 / 高位 UDP
11. 部署最小 HY2，真实使用几天
12. 再决定长期续费、加 WARP 或备用入口
```

关键原则：

> **一次只验证一层，不要先买一年，也不要先装全家桶。**

## 12. 可以这样给候选 VPS 打分

硬条件不满足的直接淘汰；剩下的再评分。

| 项目 | 建议权重 |
|---|---:|
| 本地到 VPS 的线路稳定性 | 30 |
| 晚高峰丢包 / 抖动 | 20 |
| UDP 可达性和稳定性 | 15 |
| 带宽 / 月流量 | 10 |
| AUP、售后、控制台、重装能力 | 10 |
| VPS 到目标出口 / 上游的质量 | 10 |
| 价格 | 5 |

如果最终所有流量都用 VPS Direct，可以提高“原生 IP / 出口质量”的权重。

如果主要是 `HY2 -> VPS -> WARP / Fixed SOCKS5`，则应该提高“入口线路和 UDP”的权重。

## 14. 最后一个经验：不要迷信厂商，也不要迷信线路名

今天很好的线路，几个月后可能换上游；某个地区别人很好用，在你的运营商上也可能完全不同。

所以选 VPS 最可靠的东西不是一张“神机排行榜”，而是一套可以重复执行的方法：

```text
看规则
  ↓
测线路
  ↓
月付试机
  ↓
测 UDP
  ↓
真实部署
  ↓
晚高峰持续观察
```

**实测比宣传更重要。**
