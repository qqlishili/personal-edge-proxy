# 历史 VPS 厂商候选池：只当搜索起点，不当推荐榜

这份清单来自我自己前后多轮挑 VPS / 云服务器时实际看过、比较过、注册过、测试过或使用过的厂商。

它的用途只有一个：

> **当你不知道从哪些厂商开始搜时，给你一个真实的候选池。**

不要把这张表理解成“推荐排行榜”。VPS 的库存、价格、续费、线路、上游、AUP、退款政策和节点质量都会变化；同一家厂商不同机房、不同套餐、不同批次 IP 的表现也可能完全不同。

正确用法仍然是：

```text
先明确自己的运营商 / 用途 / 预算 / 地区偏好
        ↓
从下面候选池里挑当前有合适产品的厂商
        ↓
查当前价格 / 续费 / 折扣 / 退款 / AUP
        ↓
找 Test IP / Looking Glass
        ↓
自己测白天 + 晚高峰 + 去回程 + UDP
        ↓
按“线路 50 / 价格 30 / 配置 20”或自己的权重做决定
```

## 3. 怎么使用这份候选池

### 如果你只想快速开始

先按自己的地区缩小范围，例如：

```text
日本 / 东京 / 大阪
  -> JTTI / VMISS / ExtraVM / Evoxt / Akamai-Linode / DMIT
     GreenCloud / AkileCloud / ByteVirt / HostHatch / Contabo
     以及其他当前有日本库存的厂商

香港 / 亚洲
  -> V.PS / LightNode / DMIT / HostKVM / Tencent Cloud
     以及其他当前有相应节点的厂商

美国西海岸
  -> RackNerd / Vultr / DigitalOcean / Akamai-Linode
     以及其他当前有洛杉矶 / 圣何塞 / 西雅图等节点的厂商
```

这不是固定推荐顺序，只是帮你少一点“从零开始搜”的工作。

### 如果你让 AI 帮你挑

AI 应该先问清：

```text
你的本地运营商
主要用途
长期月预算
地区偏好
```

然后再把这个历史候选池当作**搜索种子**，同时主动搜索当前市场上的其他合适厂商。

不能因为某家出现在这份表里就自动加分；也不能因为某家当年被淘汰就永久拉黑。

## 4. 每次重新看某一家，都必须重新确认

至少重新查：

```text
当前库存
真实结算价
续费价
折扣是否 recurring
退款窗口与 exclusions
公网 IPv4 / NAT
UDP 政策
AUP / ToS
月流量和端口带宽
Test IP / Looking Glass
去程 / 回程
白天 / 晚高峰
真实实例表现
```

线路尤其不能继承旧结论。

> **厂商名单可以复用，线路结论不能复用。**

今天一条很好用的日本线路，几个月后完全可能换上游；同一家厂商的不同套餐也可能走不同网络。

## 5. 最后仍然回到“不可能三角”

这份名单不是为了找“公认最好”的厂商，而是为了给每个人更快建立候选池。

最后仍然按自己的需求平衡：

```text
线路 / 稳定性
      50
      /
     /
价格 30 —— 配置 20
```

这是本项目对日常 HY2 / AI 中转的默认权重；其他用途可以重新分配。

厂商只是候选来源，**真正决定买不买的，是当前套餐 + 当前线路 + 当前价格 + 你的真实网络实测。**
