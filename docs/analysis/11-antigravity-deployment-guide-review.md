- **审查角色**：`docs-reviewer`
- **裁决结果**：`VERDICT: [FIX-FIRST]`
- **缺陷统计**：P0=0, P1=4, P2=3

---

## 审查裁决核心理由

设计方案在**物理拓扑可行性**（无法直连却通过明文 HTTP 裸拉订阅）、**极简硬件约束**（128MB 内存强塞官方 `cloudflare-warp` 必然触发 OOM，违背零外部进程原则）、**核心依赖**（缺失 NTP 同步导致 SS-2022 重放失效）以及**证书生命周期自闭环**方面存在多处系统边界脱节与 P1 级设计缺陷，必须优先修正设计。

---

## 缺陷清单与第一性原理深度剖析

### 问题 1 (P1)：订阅分发物理拓扑死锁与明文 HTTP 凭据暴露
- **现象**：文档引导客户端通过 `http://<LANDING_IP>:2096/sub/<YOUR_SUB_TOKEN>?format=clash` 直连拉取订阅。
- **根因**：物理约束已明确“物理机无法直连落地机”。客户端在无代理冷启动时访问 2096 必被 GFW 丢包超时；且明文 HTTP 传输全套 SS/Reality 凭证，在公网暴露指纹探测面。
- **修复**：废弃公网 2096 端口，改用本地离线生成 / 安全通道下发配置。

### 问题 2 (P1)：128MB 极端环境部署官方 `cloudflare-warp` 引发 OOM 崩溃
- **现象**：128MB~256MB 小鸡运行官方 `warp-svc` 守护进程。
- **根因**：Linux 基础开销 (~50MB) + s-ui (~20MB) + 官方 `warp-svc` (45~90MB) > 128MB，必触发 Linux 内核 `oom-killer` 随机杀进程。
- **修复**：在文档中按硬件规格分级：128MB~256MB 极小机推荐直接使用 sing-box 原生 WireGuard 出站，512MB 以上才部署官方 WARP SOCKS5。

### 问题 3 (P1)：缺失 NTP 时钟同步导致 Shadowsocks-2022 重放防御机制误杀握手
- **现象**：阶段一系统初始化遗漏时钟同步配置。
- **根因**：SS-2022 强制要求时间窗口在 ±30 秒内。低配 VPS 宿主机时钟漂移严重，一旦时差超 30s，所有握手均被当作重放攻击静默丢弃。
- **修复**：在系统初始化中强制配置 `systemd-timesyncd` 或 `chrony`。

### 问题 4 (P1)：方案 C (VLESS-WS-TLS) 证书生命周期在纯中转与无胶水约束下无法自闭环
- **现象**：未说明证书获取与续期方式。
- **根因**：无公网 80 端口直连，无法完成 Let's Encrypt HTTP-01 验证；无外部 Nginx/Caddy 胶水。
- **修复**：闭环方案：使用 Cloudflare 15 年 Origin CA 证书，免除续期与 80 端口负担。

### 问题 5 (P2)：VLESS-Reality gRPC 在双重 TCP (Chain Proxy) 下的队头阻塞
- **现象**：gRPC 多路复用在级联代理网络抖动时导致子流全线卡顿。
- **修复**：明确标定方案 A (SS-2022) 为第一主力，gRPC 仅作为应急拟态备选。

### 问题 6 (P2)：外部 Python 脚本直写 SQLite 缺乏备份防护
- **修复**：在脚本执行前强制执行 `sqlite3 backup` 自动生成快照。

### 问题 7 (P2)：Fake-IP 与 lancidr 规则避坑缺少 `no-resolve`
- **修复**：在客户端规则中所有私有 IP 匹配规则强制附加 `no-resolve`。
